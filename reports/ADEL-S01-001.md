# ADEL-S01-001 — Validador de recetas JSON v1

**Requisito:** `SPEC.md` §4; `PLAN.md` tarea 01.1. Implementación limitada a validación estática. Solo se usaron recetas sintéticas en pruebas.

**Interfaz:** `load_recipe(path: Path) -> Recipe`; fallas controladas con `RecipeError(code, location)`.

**RED:** `python -m pytest tests/test_recipes.py -q` terminó en error de importación porque no existía `vyntrava_data_studio.recipes`. Se añadió la implementación. Una segunda prueba RED detectó dos `TypeError` al recibir listas en `salidas[*].fuente`; se corrigieron para emitir `RecipeError`.

**GREEN y REFACTOR:** `python -m pytest -q --basetemp=.pytest_tmp` → suite aprobada. La validación se dividió en forma, versión, entradas, esquema, parámetros, operaciones y salidas. Los errores exponen código y ubicación, sin copiar valores de celdas. Una prueba RED adicional detectó desbordamiento al validar un entero JSON grande; se corrigió sin convertir enteros a flotante.

**Revisión independiente:** señaló que una versión con miles de dígitos escapaba como `ValueError` y que `tipo_encargo` se restringía a la gramática de identificador. Ambos casos tuvieron pruebas RED y corrección. La revisión también señaló `grafico_png`: el validador de esquema permite describirlo conforme al contrato v1; el motor deberá rechazar esa capacidad hasta Sprint 03, antes de abrir entradas.

**Decisiones:** el motor acepta versiones `1.0.PATCH` del contrato actual; rechaza menores futuras. El delimitador puede omitirse en la receta porque su confirmación pertenece a la ejecución. Las referencias escalares de `params` se resuelven contra `parametros` durante la carga. La confirmación de delimitadores, sobrescrituras de ejecución y control de capacidades efectivamente implementadas quedan para la integración del motor, según `SPEC.md` §4.

**Límite de evidencia:** no se procesaron CSV; esta tarea no acredita el cierre de Sprint 01.
